### The storage-key guard was rewritten, because the old one could not fail

`learning-site/scripts/test-data.mjs` asserted `KEYS.length === 9` and compared the registry against a fixture **hand-maintained in the same file**. It was therefore comparing the test to itself, and could not detect the failure it existed to prevent: a storage key the site writes but the backup does not know about. It had already broken on **two consecutive key additions (8 → 9 → 10)** while catching nothing — a hardcoded length can only restate what someone already knew.

It now scans `src/` for `cs-roadmap:*:vN` string literals and compares against `KEYS` in **both directions**: every key the site writes must be registered, and every registered key must actually be used. The duplicate, weaker `KEYS.length === 9` assertion in `scripts/test-notes.mjs` was deleted for the same reason. `test:data` is at **86 checks**.

**This was the second time in this project a guard printed nothing and was read as green** — the first was the `^0[1-9]-` pattern that hid phases 10+. It is also the third time a key-count change broke the suite. The pattern is consistent: a check that restates a number someone already believes is not a check, and its failure mode is silence rather than a red result.

**A later pass found the same class twice more, and it is now the most productive thing this project knows how to look for.** `audit-refs.mjs`'s `FORWARD_AS_PRIOR` detector had **never been capable of firing**: its call site sliced `line.slice(0, m.index + 4)` — four characters from the match, i.e. `"Phas"` — so the cue regex, which needs the literal word, could not match, and the `(0)` it reported for its whole life was not a clean corpus. `audit-terms.mjs`'s expansion detector missed four separate shapes, including the commonest one in this repo, and reported `**SPF** (Sender Policy Framework)` as never explained **on the line that explains it**. ### Rendered in a browser, once, on 2026-09-16

This section previously read "Never rendered in a browser" and carried the caveat at the top of every session. **That gap is closed.** The notes UI, the dashboard rail, the print stylesheet, the Shared view, the Your work view and the time-budget control were rendered in a real engine on 2026-09-16 by `learning-site/scripts/browser-check.mjs`, which drives it over the DevTools Protocol with **no test dependency** (Node 24 ships a global `WebSocket`). **79 checks, 0 failed.** It runs in CI, where `ubuntu-latest` has Chrome at a known path, so it is a standing guard rather than a one-off. See D-023.

What it asserts that a string render cannot: computed CSS, layout geometry, media-query behaviour, and focus survival across keystrokes. The two assertions worth naming are **focus survival** (the driver types one character, asserts the textarea still has focus, types a second, asserts the value accumulated — a panel that remounts per keystroke is a real React defect invisible to any test that sets `.value` once) and **the print media query actually applying** (`Emulation.setEmulatedMedia({media:'print'})`, then assert the sidebar computes to `display: none`, card borders to `none`, `--bg` to `#ffffff`, `break-inside: avoid` on code). Both real writes are verified through the real storage key, and `Your work` is asserted in a live DOM to carry no `N of M`, no percentage and no `role="progressbar"`.

**The honest result: it found no site defects.** Its first run reported three failures and all three were the driver's own fault — it measured anchors on whichever Shared document opens first, while the resources list is the third. That is recorded in the script's comment and in D-023 rather than quietly fixed, because "the browser check found nothing" is only good news if the check is known to be able to fail.

**A skip cannot masquerade as a pass.** The script exits 0 with an explicit `SKIPPED` line when no browser is found, which is right for a contributor's machine and wrong for CI — `completed / success` cannot tell that apart from a passing run. The workflow therefore sets `BROWSER_CHECK_STRICT=1`, which turns a missing browser into a failure, and the script also fails if fewer than `MIN_CHECKS` (40) ran, which catches a run that connected to an error page and asserted almost nothing. Both paths were exercised locally — strict with no browser exits 1, non-strict with no browser exits 0 — and **CI run #45 passed the step with strict mode on**, which is the end-to-end proof that the runner has a browser and the checks executed. `BROWSER_PATH` exists so the skip path is testable without breaking `PATH` and hiding `node` itself.

**The band this section used to name as a gap is now covered, and covering it found a defect in the check rather than in the site.** The check previously ran two widths; it now runs **seven** — 1180, 1179, 900, 861, 860, 760, 620 — with assertions placed on **both sides of each breakpoint** (1180/1179 where the dashboard grid goes two-column, 861/860 where the sidebar becomes an off-canvas drawer), so each flip is observed rather than inferred. The first run at 760 and 620 produced an immediate failure: `rail: has collapsed by 620px — display=block width=573`. **That assertion was wrong about the site.** `global.css` declares no rail-collapse mechanism at all; the *sidebar* is the drawer below 860px and the rail simply goes full-width, so a 573px rail at 620px is correct. The assertion was replaced with ones derived from what the CSS actually declares. This is the same mistake as a guard whose skip path looks like its pass path, one level up — asserting a mechanism that was assumed rather than read.

**The engine is now named, because it was always being chosen silently.** The `BROWSERS` list tries Edge first, so every prior run measured Edge while reporting only "a real browser". The script now prints `Browser.getVersion` and asserts on it (`Edg/153.0.4234.32` locally).

**What remains true.** This is the section that overclaimed most, and it is worth being precise about what it said and what was actually true. It read: "The check drives **one engine per run** — the script identifies which one it used, and the second engine is the CI runner's `/usr/bin/google-chrome`. That second engine is no longer merely possible: **CI run #57 on `11f62e4` shows `Browser check (real engine)` as `success`**." Every word of that was accurate, and the conclusion drawn from it — that the browser question was settled — was not. **Edge and Chrome are both Chromium.** Run #57 was two builds of one rendering engine, and the claim it was cited for was cross-browser coverage. That is the same failure shape this file has recorded four times: a check whose output is true but whose *inference* is wrong.

**The correction was attempted, and it failed for an instructive reason (D-031).** Firefox was added as a CI matrix leg with an engine selected by name through `BROWSER_ENGINE`. **The leg failed on its first run, and the cause is not a bug here: Mozilla removed Firefox's CDP implementation.** Its own documentation for `remote.active-protocols` says that *"with the end of the CDP support, WebDriver BiDi is the only available protocol, and the preference was removed in Firefox 141."* This script speaks CDP, so no flag or path change can reach Firefox; it needs a WebDriver BiDi implementation, which is a different protocol rather than a configuration change.

This is where the engine-selection guard earned its place. Because a named engine that cannot be found **fails** instead of falling through, the leg reported "no browser found" and exited 1 **rather than measuring Chromium and reporting it as Firefox**. The failure was legible on the first run; a fall-through design would have shipped a green Firefox badge for a browser that never started. The unsupported engine now fails immediately with the reason printed, instead of timing out at the target lookup with "browser never exposed a page target", which reads as a flaky machine.

**The honest current claim is Chromium only** — two builds of it, Edge locally and Chrome/Chromium in CI. Gecko and WebKit are a known, named gap.

A second caveat of the same kind, still open: **nobody has timed any curriculum task.** Every band and every energy value is an authored estimate, not a measurement, and the UI says so on the page. This pass added 21 more of them.

To check a specific engine by name, set `BROWSER_ENGINE=chromium` first. **A named engine that cannot be found fails the run even without strict mode**, because a run that asked for one engine and quietly measured another would be cited as cross-browser evidence for an engine that never started. **Do not set `BROWSER_ENGINE=firefox` expecting a run**: Gecko is a recorded dead end (D-031) — Mozilla removed Firefox's CDP implementation, so the script now fails immediately and prints why rather than timing out at the page-target lookup.

On Windows PowerShell, set the variable first: `$env:BROWSER_CHECK_STRICT = "1"` then run `npm run test:browser`. Without it, no browser means a skip and exit 0 — which is honest locally and is exactly why CI sets it.
