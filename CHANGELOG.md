## [Unreleased]

### Fixed
- **A beginner-comprehension audit of all 23 phases found four structural classes of defect, and all were repaired.** The audit asked one question the existing guards structurally cannot: *where does a motivated beginner with no IT background stop reading, and why?* Nine readers covered three phases each, reporting only falsifiable findings with a line number and a quote, and every finding was re-checked against the source before a fix was applied — **two were rejected as wrong**.
  - **A demonstration that silently fails.** IT 05 Check 5 denied read on `C:\P5-AccessLab\Child`, then read a file in the *parent* folder and told the reader the Deny had won. The reader's own output contradicted the lesson. The check now writes the test file into the denied folder and reads it back from there.
  - **A worked artefact that is impossible as printed.** Cyber 05's weighted totals (82/63/88/61) cannot be produced from its own table, whose weights sum to 14 — a ceiling of 70; recomputed to 58/47/61/44, which also corrects the line-522 "within 5 points" near-tie remark. Cyber 06's priority formula encoded 6 of the grid's 16 impact/urgency pairs, returned `P2` where the grid says `P1`, and indexed a 4-row range with entries 5–6. Cyber 14 stated a CVSS of **7.1** for a vector that computes to **6.5**, against its own band table that calls 6.5 Medium.
  - **A cross-reference to a section that does not exist, or that says the opposite.** IT 06 sent the reader to "Part 5's structure" for the escalation note, which is in Part 4; IT 07 referred to a nonexistent "Part 8"; cyber 03 claimed Phase 1 defined `least privilege` and `access review`, and Phase 1 never does — both are now defined inline at first use.
  - **A contradiction inside one phase.** IT 09 set two different application targets (5–8 vs 15), three different follow-up intervals, and two different tracker column lists; cyber 09 advertised a conditional-access lab that its own text later says needs a paid licence, and now says where the free tier stops.
  - **One phase was judged "would abandon":** IT 02's Ticket 2 runs entirely on a Windows domain and `Get-ADPrincipalGroupMembership` for a reader whose stated machine is a home PC. It now says so rather than leaving the reader to conclude they misconfigured something. IT 02's `systemctl status ssh` on Ubuntu **Desktop** (which ships no ssh server) gained the `apt install openssh-server` line, its `awk` and `icacls` invocations were glossed, and the "third command" with no referent now names the command.
  - **A checklist row claimed a paid feature was free.** `cybersec-roadmap/checklist-master.md` said "I enabled MFA and a conditional access policy in a free cloud tenant", while Phase 09 says plainly at line 376 that conditional access needs Entra ID P1 and "this phase does not require you to buy one". The row now matches what the phase actually asks: enable MFA for free, and be able to *explain* a conditional access policy and where the free tier stops — which is what Phase 09's skill line already said.
  - **Smaller fixes are one-clause glosses at first use, for terms that were genuinely load-bearing:** SPF/DKIM/DMARC (cyber 02, 06, 08), fail2ban (cyber 04), disposition (cyber 05), SID (cyber 06), Kerberos/TGT/Kerberoasting/NTLM (cyber 10), legal hold (cyber 11), CISO and the SOC 2 CC numbering (cyber 13), JWT (cyber 14), PSA and CompTIA A+ (IT 09), tenant and subscription (cyber 09). IT 01's "2–4 hours" for a 25,000-word lesson now reads per Part, because the old figure made a beginner read their own honest pace as failure.
  - **Broken code the reader was expected to run.** Cyber 10's Wazuh rule used a positive `<field>` match for the known-benign parents, so it fired when the parent *was* the management tool — the inverse of the Sigma and SPL versions it was presented as equivalent to; it now carries `negate="yes"` and the equivalence claim says why. Cyber 12's corrected auto-closer raised `NameError` on `evaluated`, never defined; its `from lookup import` had no file to import from; and its README setup was Unix-only (`export`/`grep`/`cut`) in a Windows-targeted curriculum. Cyber 10's auditd rules had no target file and no load command, so the exercise could not be carried out.
  - **Guards after the edits:** readability **0 of 23** phases outside target (cyber 08 held at 18 words/sentence, the ceiling), lint 143 files / 0 issues, lesson AST 23 lessons / 0 content loss, 0 paragraphs over 150 words, cross-references 0 broken.
- **A cross-reference guard, because the audit proved exactly one class is machine-checkable** (D-022). **`scripts/audit-refs.mjs`** exits 1 on a `Part N` reference to a heading the file does not have, or a `Phase N` reference to a number the track does not contain, and runs in CI. It found the IT 06/IT 07 defects and then independently confirmed the cyber 11:64 forward-phase citation. `FORWARD_AS_PRIOR` is printed but does not gate: the guard was wrong about it once already, matching "risk reasoning **from** Phase 13 arrives later" — a sentence that disclaims prior knowledge — as a claim of it.
- **[`docs/COMPREHENSION-AUDIT.md`](docs/COMPREHENSION-AUDIT.md)** records the findings by phase, the two rejected claims, and a negative result: `scripts/audit-terms.mjs` does not converge after five measurement passes (365 → 232 → 232 → 227 domain terms), so it is retained as a measurement that always exits 0 rather than shipped as a noisy gate. The residue was `AMD`, `USD`, `UTC`, `PID`, `NTFS`, `CMD`, `ISP`, `SSID` — two brands, a currency code, and `PID` flagged on the line that defines it.

### Added
- **Practice tasks now say how long they take, and the dashboard asks how long you have** (D-021). The dashboard had always answered *what should I do today* with the next unfinished checklist item, and it could not answer the question a real beginner asks every day: **I have forty minutes. Is this a forty-minute task?** The curriculum's practice tasks ran from *plug in a USB stick and watch Device Manager* to *install VirtualBox and build an Ubuntu VM* to *practise twenty technical interview questions across eight topics*, and nothing in the data distinguished them. A reader with half an hour was handed the VM.
  - **Bands, not minutes — and the number was measured before it was rejected.** 82% of the 183 practice tasks sit between 20 and 90 minutes, so any cut inside that range is an arbitrary line drawn through a continuum. Only two honest edges exist: under ~20 minutes is essentially empty (4 tasks), and over ~90 minutes is *structurally* different rather than merely longer — multi-session projects, tool-curriculum cliffs, writing volumes. Phase-level durations (weeks, or "60–80 hours") were rejected as two to three orders of magnitude too coarse to schedule a Tuesday afternoon, and word count and verb choice were measured and carry almost no signal: "Install VirtualBox" (90 min) sits in the same phrasing family as "Install CrystalDiskInfo" (20 min).
  - **`ongoing` is an exclusion path, not a length.** It means *more time would not help* — recurring, week-gated, multi-session or hardware-gated work — so such a task is never offered as a suggestion and `fitsBand` fails **closed** on it in both directions.
  - **Every band is an authored estimate and the UI says so on the page.** Nobody has timed a single one of these tasks, and presenting a guess with the confidence of a measurement is the failure this label exists to prevent.
  - **A real defect the new test caught, not a reader.** An unaddressed `ongoing` task left `smallestBlocking` null and fell through to `all-addressed`, so the dashboard would have told a reader **"nothing left" while they still had work** — just not work that fits in one sitting. That is the one sentence the page must never get wrong. The taxonomy was split rather than the test relaxed: `only-ongoing` and `unjudged` are now distinct reasons with their own honest messages, and the old two-branch "nothing left" message is gone.
  - **All 183 practice tasks now carry authored metadata and ZERO ids are minted from position.** The build reports `task bands: 183 banded, 0 authored without a band, 0 still minted from position` and `task energy: 183 of 183 practice task(s) carry an energy value`. Tallies — **bands:** quick 23, focused 115, deep 34, ongoing 11 (IT 70: 11/49/6/4; cyber 113: 12/66/28/7). **Energy:** low 26, normal 128, high 29 (IT: 11/55/4; cyber: 15/73/25). The `energy:` field was also back-filled onto all 183 task lines, which previously carried it only on checklist items.
  - **`learning-site/src/lib/today.js`** is pure — `BANDS`, `bandInfo`, `fitsBand`, `addressedTaskIds`, `pickToday` — so the whole picker runs under plain Node. `addressedTaskIds` has exactly two rules and introduces **no new progress system**: a task with a non-blank answer, or every task in a phase whose checklist is fully ticked (an empty checklist must **not** count as complete). `pickToday` walks curriculum order and never reorders, returning one of `ok`, `no-budget`, `empty`, `all-addressed`, `none-fit`, `none-fit-energy`, `only-ongoing`, `unjudged`.
  - **The dashboard draws its suggestion from practice tasks** — which carry bands — **rather than the checklist**, which does not, via the new `allPracticeTasks(track)` in `data/roadmaps.js`. The progress ring and percentage are unchanged: progress still counts the checklist, and the two lists are different on purpose.
  - **The time budget is a tenth `localStorage` key**, `cs-roadmap:time-budget:v1`, registered in `lib/transfer.js` → `KEYS` so backups carry it. The backup registry grew from 9 to 10. It defaults to `focused`, because that is where 82% of the tasks actually sit and so is the least wrong guess for a reader who has never touched the control. `components/TimeBudgetSelector.jsx` matches the existing energy control's shape, carries a visible note that the durations are estimates, and deliberately does **not** offer `ongoing` as a budget — that is a property of a task, not an amount of time a person can have.
  - **`learning-site/scripts/test-today.mjs`** — **77 checks** across the band table, fitting in both directions, the addressed rules, ordering, and every reason. Wired in as `test:today`.
- **A `Your work` view that reads back everything the reader has written** (D-020). D-019 shipped the writing side and deliberately no reading side, so a note was reachable only by navigating to the phase that owned it. Writing that can only be found by remembering where you put it is a silo, not a workspace.
  - **`learning-site/src/lib/yourWork.js`** is pure — no React, no DOM — and **`pages/YourWork.jsx`** renders it: every phase note and every per-task answer across all 23 phases, on one page, each linked back to the phase that owns it.
  - **Answers are matched to tasks BY ID, never by position**, and an answer whose task no longer exists is **kept** and flagged `orphaned: true` rather than dropped. Deleting the reader's writing because the curriculum moved would destroy the one thing on this site that cannot be regenerated.
  - **The page carries no denominator, and that is structural.** `summariseWork()` returns `{ phases, notes, answers, orphaned }` and deliberately has no `total`, `percent` or `remaining` field, so the absence cannot be undone by accident. No "of 23", no percentage, no progress bar, no ordering by volume — the summary says how many phases hold writing, which is a statement about where things are, not how much is done. This follows the no-shame rule D-019 established for the writing side.
  - **It reads via `readNotes()`, not `useNotes()`**, so it never becomes a second live copy of the `localStorage` key — the same discipline the dashboard rail follows with `readPortfolio()`. The empty state names the notes panel and the answer boxes, so a first-time reader knows where writing happens.
  - **`learning-site/scripts/test-work.mjs`** — **31 checks** across curriculum ordering (not store key order), id matching, orphans and the summary. Wired in as `test:work`.
- **A `Shared` view that surfaces `career-roadmaps/shared/` in the site** (D-020). The anti-burnout rules, the 42-resource list and the weekly tracker template have always been part of the curriculum and had **no path to them from the site** at all, because `scripts/build-content.mjs` walks for `*-phase-*.md` and these are not phase files. The reader those documents were written for — someone on a 34–112 week plan at risk of burning out — was the one least likely to ever see them.
  - **`scripts/shared-content.mjs`** emits `learning-site/src/data/generated/shared.json` — 3 documents, 40 blocks, 42 resources, 20 KB — and reuses the existing lesson parser through a new `headingBase` parameter rather than forking it. Lessons are authored inside a `## Lesson:` wrapper so their headings start at level 3; a standalone shared document is authored `# Title` / `## Section` and starts at level 1. One parser, two corpora.
  - **The resource list is parsed from `Name — https://url` lines, and the build FAILS** if the separator is wrong or a bullet appears before any category heading. A silently mis-parsed catalogue is worse than a stopped build.
  - **`pages/Shared.jsx`** is a chip picker (`aria-pressed`) over the three documents, and it deliberately does **not** reuse `<Lesson>`: Lesson carries a TOC with scroll-spy, per-section done controls and a reading-position bar, all keyed by phase id through `useLessonProgress`, and a shared document has no phase and nothing to tick — reusing that machinery would mean inventing a fake phase id to hang state on.
  - **Resources render from structured data as real `<a href target="_blank" rel="noreferrer">` anchors**, because `renderInline` deliberately does not autolink and 42 URLs as prose would be 42 dead ends. The smoke test asserts every resource is an href and that no bare URL is left as text.
  - **`Shared.jsx` takes an optional `initialId` prop**, read only as the `useState` seed, so a specific document can be opened directly. That is what made the resources document coverable by the smoke test, and it is the hook a future deep-link would need.
  - **`App.jsx`** gained a `shared` view in `VIEWS` (label **Shared**), placed after `search`.
- **Somewhere to write, and it is not scored** (D-019). The curriculum constantly asks the reader to produce something — nine phases were rewritten specifically to end in an artefact the reader keeps — and the site's entire support for that was **a checkbox**. A reader halfway through a 15,000-word lesson, looking at an exercise that says *write down what you noticed*, had nowhere in the site to write it.
  - **One free-text note per phase, one answer per practice task**, in a new `cs-roadmap:notes:v1` store owned by `src/hooks/useNotes.js`. Reached from the phase page as a **Your notes** panel, collapsed by default, and a **Write your answer** control on each practice task.
  - **It is a workspace, not a scoreboard, and a test enforces that.** No completion count, no “3 of 7 answered”, no percentage, and nothing here feeds the dashboard — a reader who writes one line and one who writes nothing look identical to every other part of the site. `smoke-render.mjs` asserts that the rendered output of both new components contains no `N of M` pattern, because a workspace that quietly starts keeping score is the one failure an innocent later change is most likely to introduce.
  - **Practice tasks gained stable ids, which they never had.** They were plain numbered strings, so an answer had only its array position to go on — and inserting a task above it would silently move one reader's writing onto a different question. `scripts/build-content.mjs` now mints `<phase-id>-tNN` on the same principle the checklist already follows. **Recorded limitation:** these ids come from position at build time, not an authored comment, so appending a task is safe and reordering one is not.
  - **The note and the answers merge differently, because they are different things.** A note is prose, so on import the existing one wins rather than an older draft replacing what was written here; answers are a map of id to text and union per task. A phase only in the incoming file is taken whole, which is the point of moving to a new laptop.
  - **It registered as the ninth key in `transfer.js` on the day it was written** — and that immediately exposed a gap in the backup suite, which hardcoded “eight keys” in five places and seeded only eight. The ninth threw an unguarded `JSON.parse(undefined)` that killed the whole file with a stack trace naming neither the key nor the reason, so the suite reported *nothing at all*. It now reports a missing fixture value as a failed check instead of crashing. `test-data.mjs` is at **83 checks** and a new `test-notes` adds **28**.
  - **The panel and the answer boxes do not print.** D-017 exists so a phase can be taken to a train and annotated with a pen; a page already full of the reader's own answers is a page with no room to write on. The tasks still print, with blank space after each.
  - **`test:smoke` grew from 168 to 174 renders**, covering the empty panel, the closed panel rendering no textarea, an answered task being marked with a dot rather than a count, the empty task list, and the pre-id string shape that a stale generated file would produce.
  - Bundle: **429 KB raw / 126 KB gzipped**, up 13 KB raw and 2.6 KB gzipped. No new dependency.
- **Back up and restore everything the reader owns** (D-016). Progress, portfolio, applications, schedule, reading position, section ticks and two preferences live in **eight `localStorage` keys**, and the site is local-first by design — so a cleared browser profile, a new laptop, or a reinstall destroyed months of work on a 34–112 week curriculum, silently, with nothing in the UI saying so.
  - **`src/lib/transfer.js`** exports all eight keys as one JSON document and reads it back. It is **pure** — storage is passed in as a two-method object rather than reached for as `window.localStorage` — so the entire round trip is exercised under plain Node, which is what makes the rejection cases testable rather than theoretical.
  - **Import is validated before anything is written, and one bad key fails the whole import.** Half-restoring someone's progress and leaving the rest silently behind is the one outcome a backup must not have. Unknown keys are a different case and are dropped and reported rather than refused — refusing a file over a key a newer version added would make forward compatibility impossible — while a version mismatch is refused rather than half-read.
  - **Merge unions accomplishments and keeps this machine's position and preferences.** Checklist progress, section ticks, portfolio and applications are things the reader finished, so they union; reading position and the two preferences describe *this* device and are kept, because a merge that overwrote "where I am" with a stale value would yank the reader backwards on import. Existing wins on an id collision, so importing the same file twice is a no-op.
  - **Import is a modal, not a sidebar button beside "Reset progress"** — it is the only action in the site that can overwrite work, and it does so across eight keys at once, so it lists what the file contains, key by key, and applies nothing until the reader has seen that list. **Replace** exists for restoring onto a clean machine and is the second option, spelled out and confirmed.
  - **`scripts/test-data.mjs`** — **82 checks** built around the failures rather than the happy path: a file that is not JSON, not an object, not this format, the wrong version, missing its data section, carrying a bad key of every shape, and a storage layer that throws mid-write. Also asserts the merge rules directly, including that an import can never un-tick something the reader finished. Wired in as `test:data`.
- **Find inside the lesson you already have open** (D-018). The corpus-wide box answers "where in the curriculum is this?" — a question asked *before* committing to a lesson, and one that switches views and loads a lesson per result row to answer. Once a reader is 15,000 words into one phase, the word they want is usually a few hundred words below them on the same page, and browser find (Ctrl+F) is scoped correctly but cannot rank, shows no context, and offers no jump-to-section.
  - **`src/lib/lessonSearch.js`** searches the block AST already in memory, through a deliberately smaller sibling of `useSearch.js` — same token regex, same trailing-punctuation strip, same exact-vs-loose tiers, same prefix and stem rules, same rarest-first intersection, same exact bonus — so the two boxes never disagree about what the reader typed.
  - **Two divergences from the sibling engine, both because the corpus is one lesson rather than 23.** Stopwords are a hard-coded grammatical list instead of a measured common set, and deliberately exclude content words like `user`/`data`, which still discriminate inside one lesson. An unresolvable term returns zero hits rather than tolerating it: across 23 lessons a missing term may be an indexing gap, but in one lesson it is simply absent.
  - **Section attribution is the nearest preceding h3/h4, and a heading owns itself.** A literal reading of "preceding" would attribute a hit inside `### Subnet masks` to the section above it, so the jump would land on the wrong heading. h5 starts no section because it renders as a label with no TOC entry — attributing hits to a heading the reader cannot navigate to is worse than attributing them to the enclosing section. The preamble before the first heading is still searchable; it simply has no section to jump to.
  - **A snippet is three strings — `{ before, match, after }` — not markup and not sentinels.** It renders as three text nodes with the middle one emphasised, so the module never hands HTML to a caller that would have to trust it. Sentinel characters were rejected because a sentinel can legitimately occur in lesson text; `match` is the word as actually written, sentence punctuation excluded.
  - **Every block type is indexed, including ones that do not exist yet.** Known types are handled explicitly and the `default` case walks any unrecognised block's string content under a depth cap, so a block that renders is searchable the day it appears. `buildEntries` emits exactly one entry per array position even for a malformed block, because skipping one would shift every later `blockIndex` and scroll the reader to the wrong place.
  - **`scripts/test-lesson-search.mjs`** — **77 checks** on a hand-built fixture rather than generated JSON, so it runs from a clean checkout with no build step. It reproduces the shapes that have caused real bugs here: a sentence-final term carrying its punctuation, a nested bullet, an h5 that starts no section, and a block before every heading. Wired in as `test:lesson-search`.
  - **`components/LessonFinder.jsx`** is the UI, collapsed by default behind a **Find in lesson** button in the sticky toolbar, because a reading page should not spend vertical space on a control used rarely. Escape closes it; a hit jumps to its section.
- **A phase can be taken offline on paper** (D-017). The curriculum runs 34–112 weeks and the site is local-first, but "offline" had no answer for the case that matters most to a beginner: a train, a lab bench, a machine with no network, or a reader who wants to annotate a phase with a pen. None of that needs a service worker — the browser already has a mechanism for taking a page offline on paper, and there were no `@media print` rules at all, so Ctrl+P produced the sidebar, the sticky toolbar, the reading bar and the dark theme.
  - **Everything that exists only to operate a browser is hidden** — sidebar, off-canvas nav, topbar, reading bar, sticky lesson toolbar, in-lesson finder, per-section tick controls, code copy buttons, resume prompt, prev/next pager, and every modal or overlay. What prints is the lesson: prose, code, tables, the TOC, and the phase's structured sections.
  - **The theme is repainted, not rewritten.** The site's own custom properties are overridden inside the print block, so every component rule carries over instead of each needing a print twin. The dark theme would empty a toner cartridge and is unreadable on a laser printout.
  - **Page-break rules are the substance of this, not the colour.** A code block split across a page boundary is unreadable and a table split mid-row is worse, so `break-inside: avoid` covers code, tables, blockquotes, list items and the table wrapper, and `break-after: avoid` keeps a heading with the text it introduces. A table that scrolls horizontally on screen has its wrapper set to `overflow: visible`, because a scrolled-away column on paper is simply lost.
  - **The reader's on-screen text size does not follow them onto paper.** The reading-size control scales the lesson body through a custom property, and a reader who set the largest step for a monitor would print three paragraphs to a page; prose is pinned to 11pt and code and tables to 9pt. Link URLs are deliberately **not** expanded inline — the curriculum's links are mostly documentation looked up when back online, and appending them would bury the prose in query strings.
- **A reference rail on the dashboard, and a shell that uses the width it has** (D-015). The dashboard filled the left half of a 1,919px viewport and left the right half empty — the content column was capped at 1,100px *and* left-aligned, so the dead band was a property of the shell rather than of any page. On a 34–112 week curriculum the page that answers "what should I do today" is the one the reader sees most, and it was the least informative one.
  - **The shell centres and widens.** `--content-max` (1,400px) replaces `--content-wide` as the outer cap, applied with `margin-inline: auto`; `--content-wide` remains the cap for tables, the one element allowed past the reading measure.
  - **The dashboard is two columns above 1,180px**, with a sticky rail carrying the progress ring, the plan's dates, three read-only readiness counts and the next two phases. It is a **reference column, not a second dashboard**: no charts, no streaks, no leaderboards, and its only controls are links to the page that owns each figure. Below the breakpoint it lays out as cards under the main column, in the same order — a reflow, not a truncation.
  - **Every count is phrased as "you have N", never "you are missing N".** The readiness chips report what exists outside the curriculum and link to it; nothing in the rail is a verdict.
  - **The rail reads, it does not own.** Dates come from `readStarts()`, counts from `readPortfolio()` and `readApplications()` — plain reads, deliberately not the hooks. Two live copies of one `localStorage` key drift, and the stale one writing back would drop a record the reader just added on the page that owns it. The hooks keep their subscribing behaviour for the pages that mutate.
  - **`components/ProgressRing.jsx`** — the one chart, built to the rule charts follow here: the percentage and the raw count are rendered as text beside it, the `svg` carries a label rather than being silent, and it animates nothing. A non-numeric or out-of-range value clamps instead of reaching the dash arithmetic as `NaN`, which would render as no arc at all, silently.
  - **Phase cards tile two-up** once there is width for two honest cards; fourteen full-width cards was a lot of scrolling for very little information per card.
  - **`fmtWeeks` and `fmtDate` moved into `lib/pace.js`** and are now shared with the Schedule page, so one number cannot be rounded two ways. `fmtDate` parses and formats as UTC, because formatting a UTC midnight in local time renders the previous day anywhere west of Greenwich — which turns a planned finish date into a wrong one.
  - **`test:smoke` grew from 162 to 168 renders**, covering the ring's accessible name, its drawn arc and track, both degenerate inputs, and — the assertion that matters most — that the arc is actually proportional to the value rather than merely present.
  - Main bundle: **398 KB raw / 117.7 KB gzipped**, up 4 KB raw and 0.7 KB gzipped. No new dependencies; the search index is untouched.
- **Navigation, reading position, and per-section progress across the whole app.** The site could render a 24,000-word lesson but gave the reader no way to move through one: a phase ended after its exit criteria with **no "next" anywhere**, a lesson reported no depth, and the checklist tracking completion sat below the lesson it was about. Seven `ROADMAP.md` open items are closed in this pass.
  - **Previous/next phase navigation** (`components/PhaseNav.jsx`), rendered twice per phase: a compact strip beside the Back control for a reader arriving, and a pair of cards naming both neighbours at the bottom for a reader who has finished. At a track boundary the control is present but inert and **says so** — "This is the first phase" / "This is the last phase in the track" — because a vanished control reads as a rendering bug. `data/roadmaps.js` gained `neighbours()`, which reads the phase array's order rather than the titles.
  - **Per-section done toggles inside the lesson body.** Every `###`/`####` heading carries a done control, keyed by heading id and namespaced per phase, persisted under `cs-roadmap:lesson-sections:v1`. This is a **separate concept from the phase checklist below it** and is stored, counted and labelled separately, because conflating the two would make one of them lie. Reading mode shows a quiet tick on a completed heading and reveals the control on hover or keyboard focus; **Tick off sections** turns every control visible for a review pass. A completed section also marks its entry in the table of contents, in a fixed-width gutter so the list does not jitter as sections are ticked.
  - **Reading-position bar and resume prompt** (`components/ReadingPosition.jsx`). The longest lesson runs ~15,500 words — roughly 88 screens — and the browser scrollbar measures the whole page, most of which is scaffolding *below* the lesson, so it under-reports depth through the material by a wide margin. A 2px fixed strip measures the `.lesson` region specifically, with `aria-hidden` because the table of contents already conveys the same information to a screen reader. The resume prompt is a **suggestion, never an automatic jump** — it names the section last on screen and offers a "Jump back" control, and renders nothing when that section is the one the page already opens at.
  - **A Schedule view** (`pages/Schedule.jsx`, `lib/pace.js`, `hooks/useSchedule.js`). Every phase carries `duration_weeks` — 34 weeks for IT, 112 for cyber — and nothing used the number, so "0/90 · 0%" had no reference point and could only be read as "you have not started". Setting a start date now compares work completed against calendar elapsed, with a two-bar readout, a planned finish date, a look-ahead list of the phases that fit the next 2–12 weeks, and a per-phase plan table. **Framed as a readout, not a verdict**: "behind the calendar" gets a `--warning` border accent, a factual sentence naming the normal case, and two controls to re-baseline — never a red background, per the anti-patterns in `DESIGN-SYSTEM.md`.
  - **Keyboard shortcuts** (`hooks/useShortcuts.js`, `components/ShortcutHelp.jsx`): `/` and `Ctrl`/`⌘`+`K` focus search; `j`/`n` and `k`/`p` move between phases; `g d` and `g s` go to the dashboard and schedule; `?` toggles the shortcut list; `Escape` closes it or blurs the focused field. **No shortcut toggles a checkbox** — a single unlabelled keystroke that mutates saved progress is how a reader marks four tasks done by leaning on the keyboard, and progress is the one piece of state here that is not cheap to rebuild. Keys are ignored while the target is a field, and `alt`/other-modifier combinations are never swallowed.
