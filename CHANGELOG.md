## [Unreleased]

### Added
- **Full-text search across all 23 lessons** (D-013). A build-time inverted index — term to segment id, **no prose** — emitted as `generated/search.json` and fetched once, lazily, on the reader's first search. Results deep-link across tracks and scroll to the matching heading.
  - **The obvious implementation was measured and rejected.** Storing segment text came to 1,438 KB raw / **473 KB gzipped**, because it duplicated every lesson file; an average lesson gzips to 16 KB, so that index cost roughly thirty lessons' worth of download for an occasional feature. A second attempt — windowing long segments with overlap for better snippets — was *also* measured and made it **worse** (1,438 → 1,501 KB), because overlap duplicates text.
  - **The delivered index is 180 KB as its own chunk, and `index.html` does not reference it.** The main bundle is unchanged at 105 KB gzipped, so a reader who never searches pays nothing.
  - **Three silent-failure bugs were found by testing the index against the query engine**, not by reading either one — all three returned nothing or the wrong thing without erroring:
    - Terms in more than 20% of segments were originally *deleted* to save space. A query is an AND over its terms, so one deleted term killed the whole query: `"user account locked"` found **nothing** because `user` was gone. Common terms are now kept and flagged — matched, but not allowed to narrow — and the UI reports which words it ignored.
    - Trailing punctuation was glued into terms, so a sentence ending `"...was timestomped."` indexed `timestomped.` as a separate entry from `timestomped`. Separators are now stripped; interior punctuation is kept, because `get-adprincipalgroupmembership` and `page_fault_in_nonpaged_area` are exactly what a reader pastes in.
    - An exact match suppressed broader ones. Searching `timestomping` matched only that term (modules 10, 12) and never reached the stem that would also find module 11's `timestomped` — so typing **more precisely returned fewer results**. Exact and prefix matches are now collected separately and scored in tiers. Merging them flatly was wrong in the other direction: `STAR` exactly matches the interview method but also prefixes `start`, `startup` and `starved`, drowning the lesson that teaches STAR.
  - **`learning-site/scripts/test-search.mjs`** — 41 checks over the real generated index: known-correct queries, prefix and stem behaviour, the three bugs above, ID range and ordering, empty and nonsense queries, and that every result points at a lesson file that exists. Wired in as `npm run test:search`. Like the lesson parser, a search bug does not crash the page — it returns the wrong answer — so the guard asserts on known hits rather than on the absence of exceptions.
- **`scripts/search-index.mjs`** — the index builder. Splits each lesson into heading-scoped segments (per block gives too many results, per lesson too few) and fails the build on an unrecognised block type rather than silently dropping it from search.
- **Per-paragraph density checking in `scripts/audit-readability.mjs`.** The audit gated on a per-phase *average*, which cannot see a single 190-word wall of text sitting among twenty short paragraphs — one such paragraph barely moves the mean, so a phase reported a healthy average while still being miserable to read at that spot. The script already computed `longest para` and simply never failed on it. It now counts paragraphs over 90 words and **fails the build on any over 150**. This immediately found **33 paragraphs over 90 words** across five IT files, plus one hard failure.
- **The site now renders the lessons themselves** (D-011, D-012). It previously showed goal, skills, checklist and tools but not the lesson — and the lesson region is **84–95% of every phase file**, so roughly a tenth of the curriculum was reachable only through a GitHub link.
  - **`scripts/lesson-ast.mjs`** parses a lesson into a block AST with no dependency. It supports exactly the Markdown subset the curriculum uses — measured across all 23 lessons before a line was written: `###`/`####` headings, paragraphs, bullet and ordered lists with one level of nesting, tables, fenced code, blockquotes, and inline `**bold**`/`*italic*`/`` `code` ``. There are no images, footnotes, `#####` headings, or raw HTML to support, so none is implemented.
  - **`Lesson.jsx` and `LessonBlock.jsx`** render it behind a table of contents built from the lesson's own headings, with scroll-spy. An unrecognised block type renders a visible "Unsupported block type" message rather than nothing, so a parser gap fails loudly on screen instead of silently deleting a paragraph.
  - **`audit-lesson-ast.mjs`** proves the parser is lossless: it compares each lesson's parsed blocks against its source with markup stripped and fails on any shortfall, any unrecognised construct, or any lesson with no headings. Currently **all 23 lessons, zero loss**.
- **Six new cyber modules, Phases 9–14**, because the core path names cloud, detection, incident response, scripting, GRC and web security as target roles but taught none of them: **Cloud and Identity Security**, **Detection Engineering**, **Incident Response and DFIR**, **Scripting and Automation**, **GRC, Compliance and Risk**, and **Web Application Security**. Each is 8,837–12,181 lesson words, follows the full section contract, and stays at $0 — free tiers, OWASP Juice Shop, PortSwigger Academy, DVWA, and cloud free tiers. Each carries an explicit legal and ethical boundary section: test only systems you own or hold written authorisation for.
- **Lessons ship as per-phase files loaded on demand.** Inlining them into the track indexes inflated the JS bundle from 265 KB to **1.96 MB**, so a reader who opened the dashboard downloaded the entire curriculum before seeing anything. Splitting them out returned the initial bundle to **355 KB**: track indexes fell from 1,347 KB to 137 KB (cyber) and 1,007 KB to 69 KB (IT), with each lesson a 30–170 KB chunk fetched only when its phase is opened.
- **`docs/CONTENT-SCHEMA.md`** gained a "Lesson region" section documenting the AST block types, the index/lesson file split, and why the lessons are separate files.

### Fixed
- **Two-digit phase matching in five audit scripts.** They matched phase files with `^0[1-9]-`, which covers 01–09 only, so **every guard was blind to phases 10 and above** — and `audit-lesson-ast.mjs`, written fresh in this pass, inherited the same bug and was verifying 18 of 23 lessons. All five now use `^(?!00-)\d{2}-`, which includes 10+ while still excluding `00-overview` (a strategy document with no lesson region). The readability script's track summary also hardcoded the original eight cyber phase names, averaging the six new modules into the IT track; it now derives the track from the path. **The failure mode was silence** — the guards printed a clean result while covering four fifths of the content.
- **Mojibake in `global.css`.** Six lines carried a UTF-8 em-dash that had been decoded as CP1252. The completion check rendered as a garbled double-dash string instead of a check mark; it is now `content: " ✓";`. Verified at byte level, since the file still displays as mojibake in a PowerShell console even when correct.
- **Escaped and in-code pipes in tables.** The cell splitter broke on `\|` (Nmap's `open|filtered` state) and on pipes inside a code span (an LDAP injection payload), which split one cell into two and leaked a stray backtick into the rendered page as literal text. It now honours both.
- **Nested lists over-nested.** A flat list of sibling bullets was nested seventeen deep under the first item, because the parser compared each entry's indent to the *container's* rather than to the *previous entry's*. Verified against a genuine nested list, and item counts now match the source exactly.
- **Inline formatting with bold containing code.** The curriculum writes ``**`/etc`**``, which a single-pass alternation cannot match — the bold branch excludes asterisks but not backticks, so the run was split and the markup reached the page. `renderInline.jsx` now scans once with an ordered pattern (bold and italic before code) and recurses into the inner text of a bold or italic run.
- **The smoke test's own assertion was wrong**, not the renderer: it scanned the whole rendered HTML for literal `**`, but a `markdown` fence legitimately displays `**bold**` as an example. It now excludes `<pre>` and `<code>` and checks only prose.
