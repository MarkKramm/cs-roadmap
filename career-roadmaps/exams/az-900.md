# Microsoft AZ-900 — practice questions

**Unofficial.** Written for this repository against Microsoft's published AZ-900 study guide.
Not real exam questions, not endorsed by Microsoft.

| | |
|---|---|
| **Exam code** | AZ-900 |
| **Real exam** | approximately 50 questions, 45 minutes |
| **Pass mark** | **700** on a scale of 1000 |
| **This paper** | **40 questions** — see the note below |

## Before you start

**Do this closed-book, in one sitting, in 36 minutes.** The real exam is roughly 45 minutes for
about 50 questions, so 36 minutes for 40 matches the pace — and the pace is the tightest of any
paper here.

**700/1000 is 70%**, which is **28 questions** out of 40:

| Your score out of 40 | Percentage | Verdict |
|---|---|---|
| 32–40 | 80–100% | Comfortable pass |
| **28–31** | **70–78%** | **Pass** |
| 27 | 67.5% | Fail — just under the line |
| 24–26 | 60–65% | Clear fail |
| below 24 | — | Substantially under-prepared |

**Note the pass mark is the same as SC-900 but this exam is not about security.** AZ-900 is a
general cloud-fundamentals exam — services, pricing, governance, and Microsoft's specific product
names. It is often taken first, and it is frequently mistaken for being easy because "it is only
fundamentals". Roughly **one in five candidates fail it**, almost always on service names and
pricing models rather than on cloud concepts.

**Microsoft does not publish exact question counts.** The number of questions and the time limit
are approximated and marked as approximate above. Confirm with Microsoft when you book.

## How it is weighted

Microsoft publishes three domains with **ranges**. This paper targets the midpoint of each:

| Domain | Official weight | Questions here | Share of this paper |
|---|---|---|---|
| 1. Cloud concepts | 25–30% | 11 | 28% |
| 2. Azure architecture and services | **35–40%** | 15 | **38%** |
| 3. Azure management and governance | 30–35% | 14 | 35% |

**Azure architecture and services is the largest domain at 35–40%** and is the most
product-specific — it asks what a named Azure service does and when to choose it. Management and
governance is nearly as large and is about cost, policy and tooling.

## Domain 1 — Cloud concepts (25–30%)

### Q1. What is the primary benefit of cloud computing's elasticity?

- [ ] It removes the need for backups
- [x] **Resources can scale automatically to match demand, so you pay for what you use**
- [ ] It makes all applications faster
- [ ] It eliminates security responsibilities

**Why:** **Elasticity** is the ability to add and remove resources as demand changes — which is
what makes cloud economics work and what on-premises hardware cannot do, because you buy for peak
and idle the rest of the year. It does not remove backups or security duties; both remain yours,
and the shared responsibility model says so explicitly.

### Q2. What is the difference between scalability and elasticity?

- [ ] They are identical concepts
- [x] **Scalability is the ability to handle growth; elasticity is scaling automatically in response to demand**
- [ ] Scalability applies to storage only
- [ ] Elasticity applies to on-premises only

**Why:** Scalability is the **capacity** to grow — vertical (a bigger machine) or horizontal (more
machines). Elasticity is the **automatic, demand-driven** adjustment. The exam tests the pair
because they are commonly conflated, and the distinction matters commercially: scalable but not
elastic means you still pay for capacity you are not using.

### Q3. A company wants to avoid large upfront hardware purchases. Which cloud benefit does this describe?

- [ ] High availability
- [x] **Capital expenditure (CapEx) becoming operational expenditure (OpEx)**
- [ ] Geo-redundancy
- [ ] Disaster recovery

**Why:** This is the **CapEx-to-OpEx** shift — buying servers becomes renting compute, which is
the core financial argument for cloud. High availability and geo-redundancy are about resilience,
not cost structure, and disaster recovery is a specific capability. Note that cloud is not
automatically cheaper: it moves cost from upfront to ongoing, and an underused cloud resource is
pure waste.

### Q4. Which cloud deployment model gives an organisation dedicated resources that are not shared
with other tenants?

- [ ] Public cloud
- [x] **Private cloud**
- [ ] Hybrid cloud
- [ ] Community cloud

**Why:** A **private cloud** is operated for a single organisation, whether on-premises or hosted
by a third party. The defining property is **not shared with other tenants**, which is the phrase
to look for. A community cloud is shared by several organisations with common requirements — that
is still sharing, which is why it is not the answer here.

### Q5. What does a hybrid cloud combine?

- [ ] Two public clouds
- [x] **On-premises infrastructure with public cloud services**
- [ ] Two private clouds
- [ ] A cloud with no internet access

**Why:** **Hybrid** is on-premises plus public cloud, with some orchestration between them. This
is the most common real-world arrangement and appears in questions as "some workloads stay on
premises for compliance or latency, others move to the cloud". Two public clouds is **multi-cloud**,
which is a different term the exam also uses — do not mix them up.

### Q6. Which cloud service model requires the customer to manage the operating system?

- [ ] SaaS
- [ ] PaaS
- [x] **IaaS**
- [ ] None — the provider always manages it

**Why:** In **IaaS** you rent virtual machines and manage everything above the hypervisor —
operating system, patching, runtime, application, data. In **PaaS** the provider manages the OS
and runtime; in **SaaS** you manage only your data and users. The rule to hold: customer
responsibility **decreases** as you move IaaS → PaaS → SaaS, and that single gradient answers
several exam questions.

### Q7. What is a consumption-based pricing model?

- [ ] A flat monthly fee regardless of use
- [x] **Paying only for the resources you actually use, measured over time**
- [ ] A one-off licence purchase
- [ ] A discount for long-term commitment

**Why:** Consumption-based — pay-as-you-go — is metered usage. Note the distractors carefully: a
flat monthly fee is a **commitment**, and a long-term discount is a **reserved instance**, both of
which are real Azure options and both of which trade flexibility for a lower rate. The exam often
asks which model suits unpredictable demand, and the answer is consumption-based.

### Q8. What is the purpose of an availability zone in Azure?

- [ ] To provide cheaper resources
- [x] **To provide physically separate locations within a region so a datacentre failure does not take down all copies**
- [ ] To store backups only
- [ ] To reduce network latency between countries

**Why:** Availability zones are **physically distinct datacentres within one region**, each with
independent power and cooling. Distributing across zones means one facility failing does not take
the service down — which is high availability within a region. Distributing across **regions** is
a different and stronger control for geo-level disasters. The zone-versus-region distinction is
frequently tested.

### Q9. Which is a genuine benefit of the cloud's global reach?

- [ ] Applications run without any latency
- [x] **Services can be deployed in regions close to users, reducing latency and meeting data-residency requirements**
- [ ] Data is automatically compliant with every law
- [ ] Users never need a network connection

**Why:** Global reach gives you **choice of location** — which serves both performance (deploy
near users) and compliance (keep data in a jurisdiction). It does not make compliance automatic:
placing data in a region does not by itself satisfy a regulation, and the exam includes that
distractor deliberately. Latency is reduced, never eliminated.

### Q10. What is serverless computing?

- [ ] Computing with no servers involved at all
- [x] **Running code without managing the underlying infrastructure, billed by execution**
- [ ] A discount on virtual machines
- [ ] Computing that works offline

**Why:** "Serverless" means **you do not manage the servers** — they still exist, which is the
concept the name obscures and the exam tests. The provider handles scaling and patching, and you
are billed per execution. Azure Functions is the example to know. It suits event-driven, bursty
workloads and is a poor fit for long-running steady compute.

### Q11. What is the difference between high availability and disaster recovery?

- [ ] They are the same thing
- [x] **High availability keeps a service running through component failures; disaster recovery restores service after a major loss**
- [ ] High availability applies to storage only
- [ ] Disaster recovery is cheaper

**Why:** High availability is about **avoiding** an outage through redundancy — zones, load
balancers, replicas. Disaster recovery is about **recovering** after a large-scale event that
redundancy did not survive, and is measured in recovery time and recovery point objectives. An
architecture can be highly available and still have no disaster recovery plan, which is a real and
common gap.

## Domain 2 — Azure architecture and services (35–40%)

### Q12. What is an Azure region?

- [ ] A single datacentre
- [x] **A geographic area containing one or more datacentres, connected by a low-latency network**
- [ ] A billing boundary only
- [ ] A virtual network

**Why:** A **region** is the geographic grouping — "UK South", "East US" — and it is the unit you
choose when deploying. Availability **zones** live inside it (Q8). Some services are region-specific
and some are global, which matters when a question asks about data residency: you must deploy to a
region to keep data there.

### Q13. Which Azure service provides virtual machines?

- [ ] Azure App Service
- [x] **Azure Virtual Machines**
- [ ] Azure Functions
- [ ] Azure Blob Storage

**Why:** **Azure Virtual Machines** is IaaS compute — you get a VM and manage the OS. App Service
is PaaS for web apps (no OS management), Functions is serverless (Q10), and Blob Storage is object
storage. Knowing which service is which model — IaaS, PaaS or serverless — answers a large share of
questions in this domain, because the exam often describes a requirement and asks for the right
service *type*.

### Q14. A company needs to host a web application without managing the underlying operating
system. Which service should it use?

- [ ] Azure Virtual Machines
- [x] **Azure App Service**
- [ ] Azure Blob Storage
- [ ] Azure Virtual Network

**Why:** "Without managing the OS" is the PaaS signal, and **App Service** is Azure's PaaS web
hosting. This is Q6 applied as a service choice, and it is the single most common shape of question
in this domain. A VM would work and would require patching the OS — which is exactly what the
requirement rules out.

### Q15. Which Azure service is designed for storing large amounts of unstructured data such as
images and documents?

- [ ] Azure SQL Database
- [x] **Azure Blob Storage**
- [ ] Azure Cosmos DB
- [ ] Azure Files

**Why:** **Blob storage** is object storage for unstructured data — images, video, backups,
documents — and is the answer whenever the content is files rather than records. Azure SQL and
Cosmos DB are databases for structured or semi-structured data; Azure Files provides SMB file
shares, which is a different access pattern. Matching data shape to storage type is what this
question tests.

### Q16. What is the purpose of an Azure Virtual Network?

- [ ] To store data
- [x] **To provide isolated, private networking for Azure resources, including subnets and security rules**
- [ ] To host web applications
- [ ] To manage user identities

**Why:** A **VNet** is the networking boundary — subnets, address space, and the isolation that
lets you control traffic between resources. It is the Azure equivalent of the networking in the IT
track, and the concepts carry over directly: segmentation limits how far an attacker moves. It does
not store data, host apps or manage identities.

### Q17. Which service would you use to run a container without managing servers?

- [ ] Azure Virtual Machines
- [x] **Azure Container Instances or Azure Kubernetes Service**
- [ ] Azure Blob Storage
- [ ] Azure SQL Database

**Why:** Both run containers on managed infrastructure — Container Instances for simple,
short-lived workloads, AKS for orchestrated production ones. A VM would require you to manage the
host and the container runtime. If you already know the IaaS-PaaS-serverless gradient from Q6, this
question is asking where containers sit on it.

### Q18. What is the difference between Azure SQL Database and a SQL Server running on an Azure VM?

- [ ] There is no difference
- [x] **Azure SQL Database is PaaS — Microsoft manages the OS and patching; SQL on a VM is IaaS and you manage everything**
- [ ] Azure SQL Database is cheaper in all cases
- [ ] SQL on a VM cannot be backed up

**Why:** The difference is **who patches the operating system**, and that is the only question that
matters for most decisions. PaaS removes maintenance but also removes control — you cannot install
arbitrary components or choose uncommon configurations. IaaS keeps full control and full
responsibility. Cost depends entirely on the workload, so "cheaper in all cases" is false.

### Q19. Which Azure service provides a managed relational database that scales globally with
multi-region writes?

- [ ] Azure Blob Storage
- [x] **Azure Cosmos DB**
- [ ] Azure App Service
- [ ] Azure Virtual Network

**Why:** **Cosmos DB** is Azure's globally distributed, multi-model database with multi-region
write capability — the name to know for "globally distributed database". It is NoSQL-family, which
is worth noting because questions about globally distributed writes at scale expect Cosmos DB, not
Azure SQL. Blob Storage is not a database and App Service is not storage.

### Q20. What is the purpose of Azure Content Delivery Network (CDN)?

- [ ] To store backups
- [x] **To cache content at edge locations close to users, reducing latency for static content**
- [ ] To encrypt data at rest
- [ ] To manage user accounts

**Why:** A **CDN** caches static assets — images, scripts, video — at locations near the user, so
requests do not travel to the origin region. It is the standard answer for "users worldwide report
slow page loads". It is caching for delivery, not storage, encryption, or identity.

### Q21. Which Azure service would provide a dedicated, private connection from an on-premises
datacentre to Azure that does not use the public internet?

- [ ] A site-to-site VPN
- [x] **Azure ExpressRoute**
- [ ] Azure CDN
- [ ] Azure Firewall

**Why:** **ExpressRoute** is the dedicated private circuit — it does not traverse the public
internet at all. A **site-to-site VPN** also connects on-premises to Azure securely, but it runs
*over* the internet in an encrypted tunnel. Both are legitimate answers to "connect on-premises to
Azure", and the phrase "does not use the public internet" is what separates them. This is the same
distinction as VPN versus dedicated interconnect in the Network+ paper.

### Q22. What is an Azure Resource Group?

- [ ] A group of users with the same permissions
- [x] **A logical container that holds related Azure resources for management and lifecycle purposes**
- [ ] A physical datacentre
- [ ] A type of virtual machine

**Why:** A **resource group** is a management boundary — everything in it shares a lifecycle, so
deleting the group deletes its contents. That is why grouping matters: it is how you deploy, tag,
and remove a whole application at once. It is not a security group (that is identity) and not a
physical location, though resources in a group usually share a region.

### Q23. Which service allows you to run code in response to an event without provisioning a server?

- [ ] Azure Virtual Machines
- [x] **Azure Functions**
- [ ] Azure Blob Storage
- [ ] Azure Load Balancer

**Why:** **Azure Functions** is the serverless compute service (Q10) — event-triggered, billed per
execution, no infrastructure to manage. It is the answer for "run this small piece of logic when
something happens". A VM would need to be running and paid for regardless of whether the event
ever occurred, which is precisely what serverless avoids.

### Q24. What is the purpose of an Azure Load Balancer?

- [ ] To store application data
- [x] **To distribute incoming traffic across multiple backend resources for availability and scale**
- [ ] To translate domain names
- [ ] To provide a private connection to on-premises

**Why:** A **load balancer** spreads traffic across healthy instances, which is what makes
horizontal scaling and high availability (Q11) work — if one instance fails, the others take the
traffic. It is not DNS (though Azure Front Door and Traffic Manager do global routing, a related
but distinct role) and not a private circuit.

### Q25. Which Azure service provides a fully managed file share accessible over the SMB protocol?

- [ ] Azure Blob Storage
- [x] **Azure Files**
- [ ] Azure Cosmos DB
- [ ] Azure Queue Storage

**Why:** **Azure Files** provides SMB and NFS file shares — the answer when the requirement is a
network drive that existing applications and users can mount. Blob storage is object storage and
does not present an SMB share, which is the distinction being tested; they are both "storage" and
they serve different access patterns.

### Q26. What is the difference between vertical and horizontal scaling?

- [ ] They are the same
- [x] **Vertical adds resources to one machine; horizontal adds more machines**
- [ ] Vertical is for storage and horizontal is for compute
- [ ] Horizontal is always cheaper

**Why:** Vertical — "scale up" — means a bigger machine, and it has a ceiling and usually requires
a restart. Horizontal — "scale out" — means more instances, and it needs the application to handle
being distributed but has far more headroom. Cloud platforms make horizontal easy, which is why
it is generally preferred, but the application must be designed for it.

## Domain 3 — Azure management and governance (30–35%)

### Q27. What does it mean that an Azure service is "globally available" rather than regional?

- [ ] It is free
- [x] **It is not tied to a single region — examples include Azure AD/Entra ID, DNS and Traffic Manager**
- [ ] It only works in one country
- [ ] It cannot be used with regional services

**Why:** Global services exist outside the region model, which matters when you are reasoning about
**data residency** — you cannot choose to keep Entra ID directory data in one region the way you can
with a storage account. Knowing which services are global is a practical compliance point, and
questions often use it to test whether you understand that "deploy to a region" is not universally
available.

### Q28. A team needs to migrate a large on-premises database to Azure with minimal downtime. Which
service is designed for this?

- [ ] Azure Blob Storage
- [x] **Azure Database Migration Service**
- [ ] Azure Functions
- [ ] Azure CDN

**Why:** **Azure Database Migration Service** is purpose-built for assessing and moving databases
with minimal downtime — the name states its job. The exam includes migration services as a category
worth recognising: moving to the cloud is a major use case, and Azure has named tooling for it
rather than expecting manual export and import.

### Q29. What is the purpose of Azure IoT Hub?

- [ ] To host websites
- [x] **To connect, monitor and manage large numbers of IoT devices and their communications**
- [ ] To store documents
- [ ] To manage user identities

**Why:** **IoT Hub** is the ingestion and management point for device telemetry at scale — the
answer for scenarios involving sensors or devices reporting data. It is a named service in the
architecture domain, and the exam asks about it mostly to check that you recognise the category of
problem it addresses rather than the detail of how it works.

### Q30. Which Azure compute option is most appropriate for a long-running, steady-state workload
that must run continuously?

- [ ] Azure Functions
- [x] **Azure Virtual Machines**
- [ ] Azure Logic Apps
- [ ] Azure Container Instances

**Why:** Serverless and container instances suit **bursty or short-lived** work; a steady 24/7
workload is usually cheapest and simplest on a VM or a reserved instance. This is Q7 and Q10 read
backwards — the exam tests whether you can match the compute model to the workload shape rather
than assuming serverless is always better. Choosing serverless for constant load is a common and
costly mistake.

### Q31. What is the purpose of Azure Policy?

- [ ] To store configuration files
- [x] **To enforce organisational standards by allowing or denying resource configurations**
- [ ] To monitor application performance
- [ ] To back up virtual machines

**Why:** **Azure Policy** enforces rules — "no resources outside these regions", "storage accounts
must not allow public access" — and can deny non-compliant deployments before they happen. The
preventive nature is the point: it stops the misconfiguration rather than reporting it afterwards.
This is governance as code, and it is what makes standards enforceable at scale.

### Q32. Which Azure tool provides a unified portal for managing and monitoring resources across
multiple subscriptions?

- [ ] Azure Policy
- [x] **Azure Portal**
- [ ] Azure Advisor
- [ ] Azure Cost Management

**Why:** The **Azure Portal** is the web console — the graphical management surface across
subscriptions. Policy enforces rules, Advisor gives recommendations, and Cost Management tracks
spend; all three are accessible *through* the portal but are not the portal itself. Option two is
the general answer, and the exam distinguishes general management surfaces from specific tools.

### Q33. What are Azure Resource Manager (ARM) templates?

- [ ] Backup files
- [x] **Declarative JSON (or Bicep) files that define the resources to deploy, enabling repeatable infrastructure as code**
- [ ] Cost reports
- [ ] Monitoring dashboards

**Why:** **ARM templates** describe the desired end state and Azure makes it so — which is what
makes deployments **repeatable** rather than a series of manual clicks that nobody can reproduce.
Bicep is the newer, more readable language that compiles to ARM. Infrastructure as code is the
concept to name, and repeatability is the reason it exists.

### Q34. Which tool gives personalised best-practice recommendations for your Azure resources?

- [ ] Azure Policy
- [x] **Azure Advisor**
- [ ] Azure Monitor
- [ ] Azure Resource Manager

**Why:** **Advisor** analyses your deployed resources and recommends improvements across
reliability, security, performance and cost. It is advisory — it does not enforce anything, which is
the contrast with Policy (Q31). The pair is worth holding together: **Policy enforces, Advisor
advises**, and the exam asks which is which.

### Q35. What is the purpose of Azure Service Health?

- [ ] To monitor your application's code
- [x] **To inform you about Azure service issues and planned maintenance affecting your resources**
- [ ] To track your spending
- [ ] To manage user access

**Why:** **Service Health** is about the **platform** — outages and maintenance on Azure's side,
personalised to the services and regions you use. It is distinct from **Azure Monitor**, which is
about *your* resources' performance. "Is Azure broken, or is my application broken?" is the
question this tool answers, and the exam tests that distinction.

### Q36. Which factors affect the cost of an Azure virtual machine?

- [ ] Only the operating system
- [x] **Size, region, operating system licensing, and how long it runs**
- [ ] Only the region
- [ ] Only the storage attached

**Why:** Cost is a **combination**, which is why cloud bills surprise people. Region matters because
power and property costs differ; size determines capacity; Windows licensing costs more than Linux;
and running time is the consumption basis (Q7). The exam tests this because "why is my bill higher
than expected" is the most common real Azure question, and the answer is usually one of these four.

### Q37. What is the purpose of a resource tag in Azure?

- [ ] To secure a resource
- [x] **To attach metadata such as cost centre or owner for organisation, reporting and cost allocation**
- [ ] To back up a resource
- [ ] To assign permissions

**Why:** **Tags** are metadata — and their main practical use is **cost allocation**, which is how
you answer "which department is spending this?" without guessing from resource names. They do not
enforce or secure anything; that is Policy and RBAC. The exam asks this because tagging is the
foundation of any cost-management practice.

### Q38. What is the difference between Azure Cost Management and Azure Advisor?

- [ ] They are the same tool
- [x] **Cost Management reports and analyses actual and forecast spending; Advisor recommends improvements including cost savings**
- [ ] Cost Management is for storage only
- [ ] Advisor cannot discuss cost

**Why:** **Cost Management** answers "what did we spend and on what"; **Advisor** answers "what
should we change". One is a reporting tool and the other is a recommendation engine, and they are
often used together — Advisor surfaces the saving, Cost Management proves it. Note option four is
false: cost is one of Advisor's four recommendation categories.

### Q39. Which Azure feature provides a unified way to monitor the performance and health of your
applications and resources?

- [ ] Azure Policy
- [x] **Azure Monitor**
- [ ] Azure Service Health
- [ ] Azure Advisor

**Why:** **Azure Monitor** collects metrics and logs from your resources and lets you alert on
them — it is about **your** systems, as opposed to Service Health (Q35) which is about Azure's.
Advisor recommends, Policy enforces. The Monitor-versus-Service-Health contrast is one of the most
commonly tested pairs in this domain.

### Q40. A company must ensure all new resources are created in approved regions only. Which
combination achieves this with the least manual effort?

- [ ] Manually checking each deployment
- [x] **Azure Policy with an allowed-locations rule, ideally assigned at the management group or subscription level**
- [ ] Azure Advisor recommendations
- [ ] A spreadsheet of approved regions

**Why:** Policy **prevents** the non-compliant deployment, so no manual checking is needed — and
assigning it high in the hierarchy means it applies to every subscription underneath without being
repeated. Advisor would only *recommend* after the fact, and a spreadsheet enforces nothing. This is
Q31 applied to a governance requirement, which is how the exam usually presents it.

|---|---|---|
| 32–40 | 80–100% | Comfortable pass |
| **28–31** | **70–78%** | **Pass** |
| 27 | 67.5% | Just under the line — a fail |
| 24–26 | 60–65% | Clear fail |
| below 24 | — | Do not book yet |

### If you scored under 28

The most common AZ-900 failure is **service names**, not cloud concepts. Domain 2 is 35–40% of
the exam and asks what named services do. If you lost marks on Q12–Q30, the fix is a pass through
the Azure service list — Microsoft Learn is free and authoritative — until you can say in one
sentence what each does and whether it is IaaS, PaaS or serverless.

Two ideas worth drilling because they answer several questions each:

- **The IaaS → PaaS → SaaS gradient** (who manages the OS).
- **Policy enforces, Advisor advises, Monitor observes your resources, Service Health observes
  Azure's.**

### If you scored 32 or above

AZ-900 is a **fundamentals** certificate. It demonstrates vocabulary, not capability, and it does
not qualify you for a cloud role on its own. If you intend to work with Azure, the next step is
hands-on: a free account, and building something. The curriculum's certification phase argues this
point directly — a certificate can become a substitute for the skills it was meant to evidence.
