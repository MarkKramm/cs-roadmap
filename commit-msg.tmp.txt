docs: guard the documentation's own figures, and fix three that were wrong

Six wrong numbers have been found in these docs. Five were found by accident,
while doing something else. Nothing here had ever checked a figure the docs
state about the repository, so this adds the mechanism that was missing and
fixes what it found.

Wrong figures, all stated as current:

- CHECKPOINT.md's summary row said "23 content guards, 14 site suites".
  The real counts are 19 and 15.
- CHECKPOINT.md said lint-content checked "203 files"; it checks 217. That
  line had already been wrong once, at 162, with a parenthetical warning that
  the figure goes stale. A warning is not a mechanism, so the number is gone.
- CHECKPOINT.md said build-content authored "273 practice tasks"; it is 283,
  and line 145 of the same file said 283. Two figures for one fact, in one
  file, neither checked against the other.

Added:

- scripts/audit-doc-figures.mjs -- runs the command that prints each figure and
  fails when a document disagrees. Wired into CI.
- scripts/test-audit-doc-figures.mjs -- seven controls. They assert the guard
  can fail, and that a stale figure inside a historical pass row is
  deliberately ignored: an archive is allowed to be stale. Every run ends by
  asserting both documents are byte-identical.
- A negative result worth recording: all 658 file.md:NNN citations in docs/
  resolve to an existing file and an in-range line, and all 636 claim rows
  quote the exact text at the line they cite. Checked mechanically rather than
  by sampling.

Three mistakes made while building this, recorded rather than tidied away:

- D-061: a figure nobody recomputes is a claim, not a measurement. Adding the
  guard made scripts/audit-*.mjs nineteen, so the sentence introducing it that
  said eighteen was false before it was saved. The control suite caught it.
- D-062: the control suite's restore was registered on process.on("exit"), so a
  crashing control wrote a stale snapshot over the working tree and silently
  deleted three real edits. Reading the "pristine" text from git show HEAD: was
  worse -- the suite then tests the committed document. The restore now lives
  in each fixture's finally, against a startup snapshot.
- D-063: PowerShell's Get-Content rendered a correct em-dash as mojibake and
  the file was nearly "repaired" on that basis. Node showed valid UTF-8. Read
  the bytes, not the console -- the fix for a misdiagnosed encoding bug is a
  rewrite, which is how real mojibake gets introduced.

Verified: 41/41 CI node commands exit 0; encoding 230 files clean; changelog
guard 0 findings; validate-ci 57 steps sound.
